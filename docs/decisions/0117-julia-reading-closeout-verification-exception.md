# ADR 0117: Close verified Julia reading under an explicit bounded exception

- Date: 2026-09-12
- Status: accepted under `JULIA-STARTUP-READING.3.2`; explicit director approval
- Tags: reading, verification, continuity, defects, task-tree

## Context and authorization

The director answered **Granted** to the one-time Julia reading-only canonical
CI/receipt exception proposed and committed under `.3.1` at `d62999c12`.
This is explicit approval for this exact Julia closeout, not an extension of
ADR0114's Dart decision or ADR0116's containment-only exception.

All 52 Julia reading children are committed at physical checkpoint `2c70957a2`.
The independent audit verifies 95 source entries, 75,984 lines, 2,693,170 bytes,
exact committed scopes/comprehension/results and first-parent activation pointers.
All 122 touched fact cards and 27 repair roots / 80 pending nodes are preserved.

The complete unchanged Julia component gate passes 12,903 assertions, storage for
22 owners and five locked package trees, primary CLI conformance and 105 corpus
fixtures. The separately dormant authority consumer retains its committed proof;
no discovery or admission changes. Passing tests do not resolve known defects.

COMMIT.md and ADR0073 require canonical milestone proof ordinarily. Current
canonical CI still contains dependency-building routes that conflict with the
required PGEN/RGX build-on-submodule-update lifecycle. Startup .80.1-.4 own its
implementation, behind the remaining reading/policy prerequisites. The approved
exception permits required source reading to continue without changing those gates.

## Decision

Reexecute the committed source/commit/repair audit and exact component-log checks,
then close only Julia reading container `.1`, reading closeout `.3/.3.2` and
`SESSION-STARTUP-READING.3.5`. Route startup `.3.6` Lua decomposition after the
clean per-leaf commit and zero-byte message file.

Use focused verification for this one documentation-only reading closeout and
waive its canonical CI run and receipt. Reuse the unchanged passing Julia component
proof without claiming a new component execution. Run every normal doctrine hook,
Knowledge synchronization, memory checks, both history-pressure checks, rendered
book verification, prior-evidence preservation and current-frontier agreement.

This decision changes no runtime, test, dependency, gate, receipt implementation,
standing policy, capability, dormant admission or documentation capacity. It
permits no PGEN/RGX rebuild and waives no later repair, admission or final push
verification. No canonical receipt is generated or claimed. Normal hooks stay on.

## Consequences

- Julia source comprehension is complete and independently durable, allowing Lua
  reading to proceed; full-codebase reading remains incomplete.
- All 80 Julia repair nodes remain open with their original acceptance criteria.
  Logging and reading are not remediation or a zero-defect claim.
- Shared repairs, inherited authority issues, artifact liveness, dependency build
  reuse and all existing startup implementation prerequisites retain their owners.
- Formal mdBook reconciliation and policy adoption still follow required codebase
  reading. Parked authoring and format/language proposals remain parked.
- Future executable changes require fresh affected-surface proof. This approval
  cannot authorize another milestone, capacity change or push exception.
