# Recurring semantic-introspection gate

The recurring layer owns orchestration, not a seventh semantic representation. Its one fail-fast driver creates
one repository-filesystem artifact root and invokes the six already-admitted consumers unchanged. Those consumers
remain authoritative for strict source normalization, compiled/failed/observed snapshots, native/loaded/
reconstructed/generated/emitted/traced/isolated routes, all twenty responses, privacy, pages, budgets, portable
errors, explanations, request/response isolation, query non-execution, and host-leak denial.

The primary CLI deliberately has no semantic-introspection option. The recurring projection therefore runs only
`success_named_source_literal_input`, `failure_compile_precedes_input_load`, and
`trace_failure_invoke_route_low` across the five commands and both option environments. Those 30 legs are negative
compatibility proof. Generated-source, capability, and language-coverage checkers remain separate support
authorities.

Canonical CI always requires and syntax-checks the driver. `LINKEDSPEC_RUN_SEMANTIC_MATRIX=1` opts into the
expensive all-toolchain execution. Seven mutations independently lock runtime presence, exact commands, the
primary inventory, support inventory, canonical switch, driver path, and recurring status. The former premature
recurring mutation now denies premature MCP promotion. Thin MCP and public no-drift remain pending.

All temporary build, native-module, and writable-depot state derives from the driver artifact root. Rust and Julia
receive child roots there; Lua continues through `run_lua_project_data.sh`. The command is governed by the exact
outside-cwd routing and tool-storage owner censuses.
